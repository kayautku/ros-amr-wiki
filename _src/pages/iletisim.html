Topic ve mesaj

Bir topic, adı olan bir veri kanalıdır. Kanala yazana publisher, dinleyene subscriber denir; birbirlerini tanımazlar. Lidar sürücüsü /scan'e yazar, hangi node'ların dinlediğini bilmez. Bu gevşek bağlılık, bir bileşeni (örneğin planlayıcıyı) diğerlerini bozmadan değiştirebilmeni sağlar.

Kanaldan akan veriye mesaj denir ve her topic'in sabit bir mesaj türü vardır. Tür, alanları tanımlayan küçük bir dosyadır. Özel bir mesaj tanımı (örnek):

# myrobot_msgs/msg/RobotStatus.msg
string state             # "IDLE", "NAVIGATING", "DOCKING"
float32 battery_percent

Python'da publisher ve subscriber

#!/usr/bin/env python3
import rospy
from std_msgs.msg import String

rospy.init_node("talker")
pub = rospy.Publisher("chatter", String, queue_size=10)
rate = rospy.Rate(1)                  # 1 Hz
while not rospy.is_shutdown():
    pub.publish("merhaba")
    rate.sleep()
#!/usr/bin/env python3
import rospy
from std_msgs.msg import String

def callback(msg):
    rospy.loginfo("geldi: %s", msg.data)

rospy.init_node("listener")
rospy.Subscriber("chatter", String, callback)
rospy.spin()                          # callback'leri bekle

/cmd_vel ve Twist

Robotu sürmenin standart yolu /cmd_vel'e bir Twist yazmaktır. Diferansiyel sürüşlü bir robot iki alanı kullanır:

  • linear.x: ileri hız, m/s (negatif = geri)
  • angular.z: dönüş hızı, rad/s (pozitif = saat yönünün tersi)

Diferansiyel sürüşlü robot yana kayamaz, o yüzden linear.y hep 0'dır. Sürücü katmanı (Gazebo'daki diff_drive eklentisi ya da gerçek robotun sürücüsü) bu ikiliyi sol/sağ tekerlek hızına çevirir. Birimler (metre, saniye, radyan) REP-103 ile standarttır: dereceyi hiçbir ROS mesajında kullanma.

Dene

Bir simülasyon robotu açıkken (ya da turtlesim'de /turtle1/cmd_vel ile) ileri gönder:

rostopic pub -r 10 /cmd_vel geometry_msgs/Twist "linear: {x: 0.2, y: 0, z: 0}
angular: {x: 0, y: 0, z: 0}"

Ctrl+C ile durdur. Robot kayabilir; kesin durması için x: 0 gönder.

Servis

Servis, istek-cevap çiftidir: istemci soruyu sorar, cevap gelene kadar bekler. Kısa, hemen biten işler için uygundur (bir ayarı değiştir, bir haritayı sıfırla, bir değer hesapla). Tanım dosyası iki parçalıdır; --- isteği cevaptan ayırır:

# myrobot_msgs/srv/ComputeEta.srv
float64 distance      # metre
---
float64 seconds       # tahmini süre

Sunucu tarafı (Python):

from myrobot_msgs.srv import ComputeEta, ComputeEtaResponse

def handle(req):
    return ComputeEtaResponse(seconds=req.distance / 0.5)   # 0,5 m/s varsayımı

rospy.init_node("eta_server")
rospy.Service("compute_eta", ComputeEta, handle)
rospy.spin()

Bir AMR'da gördüğün hazır servis: /move_base/clear_costmaps (costmap'teki eski engelleri temizler).

Dene

Sunucu çalışırken: rosservice call /compute_eta 10. Çıktıda seconds: 20.0 görürsün.

Action

Bir robotun "şu noktaya git" işi saniyeler ya da dakikalar sürer. Servis bu kadar beklemez, topic ise sonucu geri bildirmez. Action ikisinin karışımıdır: istemci bir goal gönderir, sunucu ilerleme (feedback) yollar, iş bitince bir result döner ve istemci işi istediği an iptal edebilir.

Tanım dosyası üç parçadır (goal / result / feedback):

# myrobot_msgs/action/Dock.action
# Goal: yanaşmayı başlat (parametreler node'un kendi ayarlarından okunur)
---
# Result
bool success
string message
---
# Feedback
float32 distance_remaining

Bir AMR'da iki temel action var: navigasyonun move_base'i (hazır; türü move_base_msgs/MoveBaseAction) ve senin yazacağın dock gibi görev action'ları.

Python'da istemci tarafı:

client = actionlib.SimpleActionClient('move_base', MoveBaseAction)
client.wait_for_server()
client.send_goal(goal)
client.wait_for_result(rospy.Duration(60))   # en fazla 60 sn bekle
if client.get_state() == actionlib.GoalStatus.SUCCEEDED: ...
client.cancel_goal()                         # vazgeç
Dene

Hazır bir action istemci arayüzü: rosrun actionlib_tools axclient.py /dock myrobot_msgs/DockAction. Küçük bir pencere açılır, "SEND GOAL" ile goal gönderir, sonucu izlersin. Sunucunun çalışıyor olması gerekir. axclient.py, Noetic'te actionlib değil actionlib_tools paketindedir (sudo apt install ros-noetic-actionlib-tools) ve bir pencere açtığı için grafik ortam ister.

Goal'un alabileceği tüm durumlar ve SimpleActionClient'in tüm metotları için: actionlib referansı.

Parametre sunucusu

Master, node'ların ortak kullandığı bir ayar defteri de tutar. Ayarlar /isim/alt_isim biçiminde yol adlarıyla saklanır. Kodu değiştirmeden davranışı değiştirmenin yolu budur.

Python'da ~ işareti "bu node'un özel alanı" demektir. docking_node adlı bir node'da:

rospy.get_param("~kp", 0.006)   # /docking_node/kp okunur, yoksa 0.006

Parametreleri genelde bir YAML dosyasından launch ile yüklersin:

# myrobot_docking/config/docking.yaml
hsv_lower: [100, 60, 40]
hsv_upper: [140, 255, 100]
forward_speed: 0.15
kp: 0.006
Dene

Çalışırken bir değeri oku: rosparam get /move_base/controller_frequency. Tümünü listelemek için rosparam list.

Dikkat

Node kodu parametreyi genellikle başlangıçta bir kez okur. Çalışırken rosparam set yapmak, node yeniden başlatılmadan etki etmeyebilir. dynamic_reconfigure destekleyen node'larda (move_base'in birçok ayarı gibi) ise çalışırken değiştirebilirsin: rosrun rqt_reconfigure rqt_reconfigure.
